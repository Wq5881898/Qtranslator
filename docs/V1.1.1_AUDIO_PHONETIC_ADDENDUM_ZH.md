# Translator v1.1.1 音标与朗读更新记录

## 2026-08-21 最终安装版音标修复

- 英文单词音标只采用免费词典接口返回的 IPA，不由 OCR 或翻译模型猜测。
- 对词典中 `l̩`、`n̩`、`m̩` 这类在部分 Windows 字体中会显示为方框的音节辅音，转换为等价且更稳定的 `əl`、`ən`、`əm` 写法。
- 音标包含 Unicode 替换字符、控制字符或私用区字符时视为损坏，自动尝试词典返回的下一条有效音标。
- Windows 音标栏固定使用 Segoe UI，并新增 `consultation` 回归用例：`/ˌkɒnsəlˈteɪʃən/`。
- Bridge UTF-8 技术检查新增完整 IPA 往返验证，防止插件到 Windows 程序之间传输时损坏。

## 设计变更

Windows 桌面端将单词音标作为独立结果元数据显示，不再把音标拼接进中文文本框。`TranslationResult.Phonetic` 由浏览器 Provider 返回，界面层负责独立展示；句子和段落不显示单词音标。

桌面端新增本地 `Read aloud` 按钮。朗读输入始终是英文原文，使用 Windows `System.Speech.Synthesis.SpeechSynthesizer` 和 `en-US` 语音，不上传音频或截图。按钮在朗读过程中切换为 `Stop reading`，窗口关闭时终止语音进程；语音不可用时在状态区显示可恢复错误。

## 使用说明补充

完成翻译后点击 `Read aloud` 朗读英文原文；朗读过程中点击 `Stop reading` 停止。单词音标显示在 `Chinese` 标题旁，中文框只保留中文翻译。

## 2026-08-12 Bridge 验证隔离修复

本机已安装的 Chrome 插件可能在技术验证期间自动启动正式版 Bridge Host。旧验证与正式程序共用固定命名管道时，外部 Host 会抢占测试请求，表现为“并发收藏 Bridge Host 无响应”或验证长期等待。此次将正式管道名保留为 `wq5881898.translator.stage2`，同时允许技术验证通过进程环境变量使用一次性随机管道。该变量只传给本次验证启动的 Host，不改变安装版协议、收藏位置或浏览器扩展配置。

修复后回归结果：浏览器测试 39/39 通过，Windows 技术检查 11/11 通过，Release 编译 0 警告、0 错误。

已确认 Windows `System.Speech.Synthesis.SpeechSynthesizer` 程序集可加载。完整桌面构建需在安装 .NET SDK 的 Windows CI 环境执行。

## 2026-08-18 Chrome 本地翻译会话恢复修复

### 问题

查询 `whoosh` 等包含多个词典释义的单词时，Provider 曾在同一个 Chrome Translator 会话上并发执行“词头 + 多条英文释义”的翻译。Chrome 的本地 Translator 会话是有状态资源；部分设备会返回 `Other generic failures occurred.`，并使该会话继续处于不可用状态。Windows 程序重启不会销毁浏览器离屏页中的会话，因此后续查询仍会失败。

### 修复

- 同一个 Translator 会话内的词头和释义改为串行翻译；
- `translate()` 失败后立即销毁并清除缓存会话；
- 自动创建新会话并完整重试一次；
- 第二次仍失败时再次清理会话，并返回包含“重载插件或重启 Chrome”建议的可恢复错误；
- 平台不支持或语言包不可用等会话创建前错误不进行无意义重试，保留原有明确提示。

### 回归结果

- 浏览器类型检查通过；
- Vitest 41/41 通过；
- 新增 `whoosh` 多释义串行测试；
- 新增泛型失败后销毁、重建、恢复及下一次翻译连续可用测试；
- Chrome MV3 正式构建通过。

当前工作环境未发现 .NET SDK，因此本次没有重复执行 Windows TechnicalValidation；本次修复仅涉及随安装包分发的浏览器 Provider，不修改桌面程序或 Bridge 协议。

## 2026-08-21 Windows 与侧边栏翻译会话一致性修复

### 问题

浏览器侧边栏已经能够正常使用 Chrome 本地翻译时，Windows 端仍可能提示：

`Chrome needs a click to download the local language pack.`

原因是两条路径使用了不同的浏览器文档和 Translator 会话：侧边栏在可见页面中创建会话，Windows 请求则固定转发给没有用户激活状态的 Offscreen 文档。Chrome 偶尔要求由浏览器点击初始化语言包时，Offscreen 无法满足要求，因此出现“插件正常、Windows 失败”的分裂状态。

### 修复

- Side Panel 注册为可见的 Stage 2 翻译工作端；
- Windows 请求优先复用已打开侧边栏的 Translator Provider 和会话；
- 侧边栏不存在时才使用 Offscreen 作为后备；
- 响应与发出请求的端口绑定，端口断开只取消该端口上的请求；
- Provider 增加跨请求队列，网页翻译和 Windows 翻译不会同时并发调用同一状态会话；
- `NotAllowedError` 提示改为正确操作：打开侧边栏并点击一次 `Run local translation check`，而不是误导用户反复点击 Windows 按钮。

### 回归结果

- TypeScript 类型检查通过；
- Vitest 43/43 通过；
- 验证可见侧边栏优先于 Offscreen；
- 验证两个独立翻译请求在共享会话中串行执行；
- Chrome MV3 正式构建和 Release 校验通过。
