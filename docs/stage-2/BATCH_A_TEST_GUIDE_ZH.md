# 第二阶段第一批次人工测试说明

## 测试范围

本批次测试区域截图、内置英文 OCR、文字编辑和 Mock Provider。暂不测试正式中文翻译、全局快捷键、收藏或同步。

英文和简体中文 OCR 模型已经包含在测试包内，不需要安装 Windows 语言包，不需要 Key，也不需要联网。中文模型用于识别中英文边界，最终编辑框仍只保留可翻译的英文内容。

## 测试步骤

1. 解压 GitHub Actions 生成的 `translator-stage2-batch-a`。
2. 打开 `desktop` 文件夹并双击 `Translator.Desktop.exe`。
3. 点击 `Select screen region`。
4. 在网页、PDF、PPT 或 Word 中框选一段清晰英文。
5. 检查 `Recognized English (editable)` 中的英文，并确认可以手工修改。
6. 点击 `Run mock translation`，确认状态显示 `[模拟翻译]`、文本类型及 `provider: mock`。
7. 再次截图时按 `Esc`，确认程序能够取消并继续使用。
8. 故意框选一段纯中文，确认编辑框保持为空，并在下方看到“未检测到可靠英文”的提示。
9. 框选“图标 + 英文文件名”，确认图标产生的前导伪字母被清理，文件名仍保留；只框选图标时应提示结果不可靠。
10. 框选“中文 + 英文”的混合内容，确认真实英文保留、中文不被猜成伪英文；只有中文、时间或数字而没有英文单词时应显示提示。

建议先使用已验证页面：

```text
https://www.merriam-webster.com/word-of-the-day
```

如果 Chrome 已自动把页面翻译成中文，请切换为“显示原文”后再截图。

## 预期结果

- 截图时出现跨屏遮罩，框选结束后返回程序；
- 英文由随程序打包的模型在本地识别；
- 识别结果保留正常单词间距与大小写，不再随 Windows 中文 OCR 语言变化；
- 中文或其他低可信度内容不会以伪英文显示，原因会显示在下方状态区；
- 图标线条误识别出的前导符号或短伪单词会被清理，不影响其后的真实英文；
- 双语模型确定中文边界，英文模型校正英文字母；最终只显示真实英文、相关数字和英文标点；
- 截图仅保存在内存，不写入磁盘或剪贴板；
- Mock 结果不是正式中文翻译，这是本批次的预期行为；
- 失败或取消后按钮恢复可用，并显示明确原因。
