# Translator v1.1.6 回归测试报告

日期：2026-08-26

## 用户问题

- 浏览器侧边栏频繁停留在“Preparing local translation”，查询需要重复点击；
- Windows 端同样存在等待时间长、偶发查不到词的问题；
- 连续划词时旧请求可能比最新请求更晚返回，造成界面反应迟缓；
- 免费词典迟到会使同一单词连续点击出现不同完整度的结果。

## 根因与修复

1. 翻译页只在加载时连接一次后台 Worker，端口断开后页面仍在但不会主动重连。v1.1.6 增加翻译页端口自动重连，并保留 Bridge 的页面重建与一次幂等重放。
2. Provider 为保护 Chrome 有状态会话而串行执行全部请求，但没有淘汰已经过时的排队选择。v1.1.6 保留当前任务，只执行队列中最新的尚未开始任务。
3. 已创建的 Translator 会话仍会在每个请求前重新查询 `availability()`。v1.1.6 优先复用活动会话，只在创建新会话时检查可用性。
4. 词典请求超时后底层请求可能稍后完成，造成第二次点击获得不同结果。v1.1.6 将增强词典前台上限设为 3 秒，失败后清理缓存并进入 5 分钟冷却，稳定降级为基础翻译。

## 自动化验证

- TypeScript 类型检查：通过；
- 扩展单元与集成测试：12 个文件、55 项全部通过；
- Chrome MV3 正式构建：通过；
- 新增覆盖：翻译页重连退避、连续选择淘汰旧队列、会话可用性只检查一次、词典失败后重复点击结果稳定；
- 正式安装器仅使用产品 Desktop、Bridge Host、扩展和文档，不包含 `Translator.TechnicalValidation.exe`。

## 实机验证说明

浏览器安全边界不允许自动化工具直接控制 `chrome-extension://` 内部页面，因此发布前的自动化验证覆盖构建产物与业务链路；安装后的真实 Chrome 验收仍按 `BATCH_E_TEST_GUIDE_ZH.md` 执行连续单词、快速划词、空闲恢复和 Windows Bridge 四组用例。扩展升级后必须在 `chrome://extensions` 点击一次“重新加载”或完整重启 Chrome，确保内存中不再运行旧版本。
